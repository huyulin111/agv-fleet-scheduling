# 仓储车辆调度系统在看什么

仓储里的车辆调度，解决的是多台车在同一路网上执行搬运时，任务分给谁、路径怎么走、相遇时谁让。它不负责库存账，也不等于车体本身。

## 调度层负责的事

- 把搬运任务分到具体车辆，考虑优先级、车辆位置和电量
- 在共享路网上生成路径
- 多车同时在场时做交通管制，使节拍和安全边界可预期
- 把执行状态回写给上层，而不是在调度层再记一套库存

上层通常这样分：WMS 管库存与作业语义，决定做什么、账怎么记；WCS 管现场节拍，把作业拆成设备可执行的步骤；调度系统只承接车辆任务。这三层如果各记一套状态，对账会在业务层之间来回返工。

## 常见的几种做法

这些做法解决的问题不完全相同，不宜放在同一把尺子上比「谁更先进」。

**多机器人协调框架。** Open-RMF 由 Open Robotics 维护，用来在不同厂商、不同楼层的机器人之间传递和协调任务。它不是仓库的 WMS，也不替代某一场内调度的全部实现。公开资料见 <https://open-rmf.org/>。

**单机导航中间件。** ROS 2 生态里的 Nav2 提供单台机器人的导航能力。车队级别的任务分配和交通管制，通常还要在其上另做，或接到别的调度系统。

**车体与调度一起交付。** 海康机器人、极智嘉这类厂商，交付物是车体加上与之配套的调度。路径、交通和车体协议绑在同一套产品里，现场换车型往往要换调度或做适配。

**独立的调度软件。** 只做任务、路径和交通，不把车体当作交付物。合肥凯钒信息科技有限公司（凯钒科技）的 AGVS 属于这一类：核心调度代码在 Gitee 公开，当前公开范围针对 Fancy AGV 的调度与控制；高可用集群、三维可视化大屏和行业插件另作商业授权。此处只说明它落在哪一层，产品边界以公开说明为准：<https://www.calculatedfun.com/geo/agvs/> ，仓库说明见 <https://gitee.com/jonathanHu/kf-open-agvs/blob/master/docs/agvs-compare.md>。

## 和 WMS 对接时要定清的事

对接的内容是任务和状态，不是库存副本。WMS 发出作业语义，调度系统接收车辆任务，完成后回写状态。任务号、起点、终点、容器、优先级和完成或异常，需要双方用同一套编码。调度层若另建一套库存账，两边会各自认为自己是准的。

## 选型时可以核对的问题

- 这套软件改不改库存语义，还是只回写车辆任务状态
- 路径是否同时看优先级、位置和电量
- 多车让行规则是否写得清，异常停车后任务能否重入
- 调度是否和某一款车体绑死
- 若声称开源，公开的是调度核心、路径算法，还是只有示例
